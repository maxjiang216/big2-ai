# az_pi: Perfect-Information AlphaZero — build, optimization & findings (2026-06-11)

One-day log: built a perfect-information AlphaZero teacher for 2-player Big 2,
optimized self-play ~25x, ran 16 generations, and collected empirical findings
that inform the imperfect-information (II) distillation plan
(cf. `research/perfectdou.pdf`).

## 1. What was built

- **Search core** (`src/players/az_pi/`, torch-free): hierarchical PUCT
  (family → subgroup → leaf), sum/average backup with per-ply perspective flip,
  MCTS-solver with game-theoretic proof propagation, exact endgame negamax
  solver (≤12 total cards, 10k node budget) with a shared lock-free
  transposition memo. Memoryless NN interface: (hand, exact opp hand, trick).
- **Self-play** (`src/datagen/az_pi_selfplay.cpp`): sharded pipeline — N shard
  threads each single-threadedly pumping ~slots/N concurrent games, one
  inference thread fusing all queued shard requests into single GPU forwards.
  Parquet output matches the existing `Big2AZPlayerDataset` player schema
  (plus a `root_value` column: search posterior at each decision).
- **Eval** (`src/datagen/eval_az_pi_match.cpp`): paired deals (same shuffle,
  seats swapped), `pi:` / `classic:` seats, raw win rate + decisive-deal sweep
  share, Wilson CIs.
- **Loop** (`scripts/run_az_pi_loop.sh`): selfplay → train (mix last 3 gens) →
  gated promotion → tracking evals (skipped when champion unchanged) →
  deterministic sample games as HTML (`scripts/sample_games_pi.py`, fixed
  deals across gens, net value + search value per decision).

## 2. Optimization log (self-play, RTX 3060 laptop / i7-12700H)

| step | s/1k games | cumulative | note |
|---|---|---|---|
| baseline (400 sims) | 264 | 1x | solver memo rebuilt per `solve()` call |
| persistent solver memo | ~70 | 3.8x | proofs survive across calls/games |
| tree reuse (`advance_root`) | ~70 | — | strength, not speed (+17% CPU, deeper search) |
| parallel pump, 12 threads | 39 | 6.8x | OpenMP over slots; barrier per round |
| **shared** memo (was thread_local) | 26 | 10x | thread_local re-proved everything ×12 |
| 2048 slots steady state | 18.5 | 14x | bigger GPU batches |
| per-shard memo eviction | 16 | 16x | global 32M-entry clear thrashed mid-gen |
| sharded pipeline + no global barrier | 13 | 20x | shard threads + fusing inference thread |
| flat lock-free memo + node pools + flat groups | **8.3 @ 800 sims** | ~25x eff. | sub-linear in sims thereafter |

Key profiling lessons (perf, flat profile of the live process):

- **The solver, not the NN, dominated CPU** at every stage until fixed. The
  GPU never exceeded ~20% utilization; all gains came from the CPU side.
- `thread_local` memos silently multiplied solver work ×N threads (budget cut
  10x changed nothing — the giveaway that calls weren't budget-bound).
- The 32M-entry global memo cap was being hit mid-generation; each clear cost
  ~13% of CPU in re-proving + glibc free storms. Per-shard eviction (now:
  always-replace flat table) eliminated the class of problem.
- OpenMP pragmas inside `eval_batch` made gomp worker threads spin-wait
  between ~1ms batches: 76–90% of samples in libgomp. Removed; the pipeline
  binary has no OpenMP at all.
- Thread scaling saturates ~6–12 threads (6P+8E cores; memory-bound).
  GPU batch latency is flat ~1.2ms up to B=512 (launch-bound), 1M+ evals/s at
  B=2048 — shards as small as ~170 are fine, fusion keeps batches fat.

## 3. Correctness bugs found & fixed

1. **Proven-but-unexpanded root played PASS** (`best_move()` returned move id
   0 on an edgeless root). Reachable only via tree reuse into a solver-proven
   child; the agent passed away proven-won positions. Now solver-scored.
2. **`sample_move(τ=0)` bypassed proofs** (argmax over visits could miss a
   late-found proven win). Now defers to `best_move()`.
3. Memory freezes (3 hard lockups): node pools never shrink; at 1600 sims the
   per-slot high-water ratchet × 2048 slots ≈ 15–20GB → page-thrash froze the
   desktop (journald: "Under memory pressure"; cursor alive = hardware plane).
   Fixed: pool trim between games, eval slots free trees on completion,
   1024 slots, memory watchdog in monitoring. Node math: ~1.3KB/expanded node;
   with subtree reuse a tree steady-states at ≈ sims/(1−keep) nodes, keep≈0.8.

## 4. Search/algorithm refinements

- **No temperature sampling**: each game's fresh deal supplies diversity
  (unlike Go's fixed opening); Dirichlet root noise retained for in-position
  exploration. Sample-game transcripts are deterministic (fixed seed: same 10
  deals every generation — play evolution visible on identical cards).
- **Margins**: every proof carries the loser's final card count, propagated
  game-theoretically (winner maximizes, loser minimizes; "best over lines
  actually searched" — no extra search). best_move uses margin first, then a
  greedy lexicographic tie-break — no more passing out lost games.
- **Proven children allocate no node**: edge carries proof+margin; exact value
  backs up through the edge. Cuts endgame node count massively.
- **int32/float stats** (were long/double): group rows 32→20B.
- **Early stop on proven root**: remaining sim budget skipped.

## 6. Empirical findings

- **Sweep-share gating** (user idea): in paired deals, condition on decisive
  deals (one side wins both seats); split deals are card-decided noise. Gen
  13: raw 52.2% but decisive 90–19 — same data, 4.7:1 skill signal. This is a
  paired sign test; vastly more sensitive as models converge.
- **First-player advantage ~60/40** under strong PI self-play (57.2% gen 1,
  62.6% gen 8, 59.9% gen 14). The leader dictates combo types.
- **Deal decidedness** (gen 14, 20k deals, ply-0 net eval): 27% of deals are
  net-extreme (≥.95/≤.05) with only ~1.4% upsets; at search-posterior ≥.98 the
  upset rate is 0.00%. Contested band (.2–.8) is only 38% of deals. Net is
  excellently calibrated at the extremes. → deal screening could lift
  contested-deal density ~1.3–1.4x (held off for now).
- **Net vs search divergence**: rare big combos (e.g. a 10-card double
  straight) are systematically underpriced by both value head AND policy
  prior (rarely seen, rarely explored) — net said 0.98 for the doomed side
  five plies after the search had *proven* the loss. Search corrects what the
  net can't see; the strongest argument for distilling search-improved
  targets, not raw net outputs.
- **PI-as-teacher bias** (discussion): marginalizing PI values over hidden
  hands ≈ PIMC value; systematic optimism (clairvoyant defense, no
  information value), modest for Big 2's race-like structure. Hedging /
  keeping-options-open must come from II self-play fine-tuning (strategy
  fusion limits what averaging can provide).
- **Solver value**: proofs make endgame play exact, sharpen policy targets
  (visit distributions), and save compute via early-stop — but value training
  targets remain pure 1/0 outcomes; the solver never feeds the value head
  directly.
